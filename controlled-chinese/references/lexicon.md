# 词表

这份词表被人和 `scripts/zh-lint.py` 同时使用。**改一处必须同步另一处**，否则文档和 linter 会各说一套，团队里没人知道该信哪份。

分三类，用途不同：

- **锁定类**（1、2 节）：有官方依据或有纠纷代价。不是"建议换"，是"全篇只能有一个"。
- **填空类**（3–6 节）：词本身没有内容，必须换成数字、条件或主体。填不出来就留 `【待定：…】`，不许编。
- **删除类**（7–10 节）：删掉之后句子不丢信息。删掉，或换成具体动作。
- **不许动**（11 节）：情态词。它们是内容。

## 1. 义务与禁止（依据《立法技术规范（试行）（一）》第 14、15 条）

| 词 | 处理 | 说明 |
|---|---|---|
| 应当 | **保留，作为默认词** | 制度类文本全篇用它 |
| 必须 | 改成「应当」 | 含义无实质区别，二选一，不要混用 |
| 务必 | 改成「应当」 | 口语化，且强度不明 |
| 须 | 改成「应当」 | 文言残留 |
| 应 | 改成「应当」 | 单字容易被读成"应用"的前半截 |
| 不得 | **保留** | 用于**有主语**的句子：任何单位不得… |
| 禁止 | **保留** | 用于**无主语**的祈使句：禁止吸烟 |
| 严禁 | 改成「禁止」或「不得」 | 属于规范里点名不用的近义词 |
| 不准 | 改成「不得」 | 同上 |
| 不应 | 改成「不得」 | 同上 |
| 不能 | 视语境：规则里改成「不得」，技术限制里保留 | 「不能为空」是技术事实，不是禁止 |
| 不宜 | 改成「不得」，或说明理由后保留 | 「不宜」常用来回避表态 |
| 可以 / 可 | 保留 | 表示授权，与义务词不是一类，不要一并统一 |
| 需要 / 需 | 保留 | 它常指技术前提（需要重启），不是义务，别强行并入 |

## 2. 并列、范围、时限（同规范第 13、24、25 条）

| 词 | 处理 | 说明 |
|---|---|---|
| 和 | 无主次并列 | 互换位置不改变意思时用它 |
| 以及 | 有主次并列，前者为主 | 位置不宜互换 |
| 或者 | 选择，只指其中一部分 | 需要"两者都要"时不要用它 |
| 及 | 改成「和」或「以及」 | 文言残留，且主次不明 |
| 和/或、或/和、及/或 | **拆开**，明写「A 和 B 都要」或「A 或者 B，或两者都要」 | 这是中文里最贵的三个字符 |
| 以上 / 以下 / 以内 | **含本数**，必要时写「（含）」或改成 `≥` / `≤` | 例：「3 个工作日以上」含第 3 个工作日 |
| 不满 / 超过 | **不含本数**，必要时写「（不含）」或改成 `<` / `>` | 例：「不满 3 个工作日」不含第 3 个 |
| 之前 / 之后 / 以前 / 以后 | 补起算点和端点：`自 X 起 3 个工作日内` | 单独一个"之前"没有起算点 |
| 日 | 含节假日 | 「3 日」可能是 7 天（春节） |
| 工作日 | 不含节假日 | 与「日」不可在同一份文件里混用 |
| 天内 / 月内 | 补起算点 | 「收到后 5 天内」要写清"收到"如何认定 |

## 3. 空时间词

读者读完仍然不知道什么时候。

| 空词 | 改成 |
|---|---|
| 尽快 | 具体时长（「2 小时内」）、截止时间（「3 月 5 日 18:00 前」），或 `【待定：时限】` |
| 尽早 | 同上 |
| 及时 | 同上，并写明触发点（「收到告警后 10 分钟内」） |
| 第一时间 | 同上 |
| 适时 | 写出触发条件（「灰度到 10% 且无报错时」） |
| 随时 | 写出可用窗口，或删除 |
| 近期 / 近日 / 短期内 | 写出具体日期或周期 |
| 后续 | 写出是谁、在哪一步做 |
| 稍后 | 写出时长，或改成「页面会在 30 秒后自动刷新」 |

## 4. 空条件词

条件没写清，动作就无从执行。

| 空词 | 改成 |
|---|---|
| 必要时 | 写出触发条件；确实不设条件就删掉这个词，直接写动作 |
| 视情况 | 写出依据什么情况、由谁判断 |
| 酌情 | 写出判断标准 |
| 原则上 | 写出例外条件（「除 … 外」），或删掉——"原则"意味着有例外而你没写 |
| 按需 | 写出谁来判断"需" |
| 如有需要 | 同「必要时」 |
| 在适当的时候 | 写出时间点或触发事件 |

## 5. 空数量词

没有数字就没有验收标准。

| 空词 | 改成 |
|---|---|
| 适当 / 适度 / 适量 | 数字 + 单位（「不超过 200 MB」「2–3 人」） |
| 少量 | 数字 + 单位 |
| 若干 | 数字；范围已知就写区间 |
| 一批 / 一大批 | 数字，或写出范围与上限 |
| 一定程度 / 一定范围 | 阈值（「P95 延迟下降 20%」） |
| 加大力度 / 多措并举 | 具体动作清单 |
| 尽快提升 / 显著改善 | 指标 + 目标值 + 期限 |

## 6. 空主体词

谁来做没写，等于没安排。责任句需要**四件套：谁 + 做什么 + 交付什么 + 什么时候**。

| 空词 | 改成 |
|---|---|
| 相关部门 | 部门 / 岗位 / 角色名（「内容运营组」） |
| 有关人员 | 岗位名，或"由 X 指定" |
| 相关材料 | 逐项列出（「营业执照、开户许可、法人身份证复印件」） |
| 相关内容 | 写出范围或引用条款号 |
| 相关要求 | 引用文件名 + 条款号 |
| 有关单位 | 单位名 |
| 由 … 负责 | 补交付物和时间：`运维组在 T 日 22:00 前执行上线，产出上线记录` |
| 配合 / 协同 | 写出配合方要交什么、什么时候交 |

## 7. 虚动词

动作被冻成名词，前面垫一个不承载信息的动词。

| 虚动词 | 改成 |
|---|---|
| 进行优化 | 优化 |
| 进行分析 / 加以分析 | 分析 |
| 予以处理 | 处理 |
| 作出安排 | 安排 |
| 给予支持 | 支持 |
| 开展检查 | 检查 |
| 实施整改 | 整改 |
| 对配置进行修改 | 修改配置 |
| 就 … 进行讨论 | 讨论 … |

## 8. 行话

不指任何具体动作，只指"我们做了很专业的事"。改成具体动作。

| 行话 | 改成 |
|---|---|
| 赋能 | 让 X 能做什么（写出能力变化） |
| 抓手 | 具体措施名 |
| 闭环 | 写出流程的首尾：谁发起、谁确认、如何算结束 |
| 打通 | 写出打通的两端和方向 |
| 链路 | 调用路径，或直接写组件名 |
| 颗粒度 | 粒度、精度，或写出具体单位 |
| 对齐 | 同步、达成一致，或写出谁和谁对什么 |
| 沉淀 | 归档、写入文档，或写出产物 |
| 组合拳 | 逐条列出措施 |
| 护城河 / 壁垒 | 写出具体的不可复制之处 |
| 降维 / 颠覆式 / 第一性原理 | 写出实际做法 |
| 心智 / 势能 / 飞轮 / 生态位 | 写出实际指标或机制 |
| 顶层设计 | 写出范围和决策事项 |

## 9. 套话

删掉之后句子不丢信息。

需要注意的是｜需要指出的是｜值得一提的是｜众所周知｜总的来说｜综上所述｜在一定程度上｜从某种意义上说｜毋庸置疑｜显而易见｜不得不说｜不难看出｜也就是说｜事实上（作填充语时）

处理：**整句删掉**，或把"注意"后面的那句话直接留下。不要用"请注意："替换——那是同一个东西换了身衣服。

## 10. 双重否定

读者要算两次才知道你是肯定还是否定。

| 双重否定 | 改成 |
|---|---|
| 不无道理 | 有道理 |
| 未必不可 | 可以 |
| 不能不 | 必须 |
| 无不 | 都 |
| 未尝不 | 也 |
| 不排除（作可能性判断时） | **保留**——这是情态，见第 11 节 |

## 11. 同义组：一词一义

同一件事在一篇里只用一个名字。linter 在同一文件内检查：组内出现第二个词就报，并指出第一个是哪个。

| 组 | 说明 |
|---|---|
| 删除 / 移除 / 清除 | 指同一件事时选一个 |
| 用户 / 客户 / 使用者 / 会员 | 指同一批人时选一个；确实是两类人就分开定义 |
| 修改 / 更改 / 变更 | 选一个 |
| 开始 / 启动 / 开启 | 选一个 |
| 显示 / 展示 / 呈现 | 选一个 |
| 获取 / 拉取 / 读取 | 选一个 |
| 发送 / 推送 / 投递 | 选一个 |

**不收进同义组的**：错误 / 故障 / 失败（三个不同概念）；查看 / 查看并编辑（不同权限）；应当 / 可以（义务 vs 授权）。收得越松，误报越多，最后整份词表会被关掉。

## 12. 不许动的词

这些是**情态**，承载作者的置信度，是内容。删掉它们不会让句子更清楚，只会让句子更假。

可能｜也许｜大概｜估计｜大概率｜或许｜不排除｜倾向于｜我判断｜据 … 反映｜有时

处理：**照写**。句子因此超过字数上限就让它超，并在需要时用「保留原样」行说明。

判断口径：**把词删掉，句子的真假会不会变？** 会变 → 情态，保留。不会变 → 空词，处理掉。

## 13. 术语首次定义

自造词、内部缩写、跨部门黑话，首次出现时给一句定义，之后只用它。一行就够：

> 灰度：把新版本先放给 5% 的用户，观察 30 分钟无报错后再全量。

跨文档的一致需要一份项目术语表，本技能不替你维护。
