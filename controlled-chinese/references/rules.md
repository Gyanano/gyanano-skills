# 受控中文规则全集与依据

这份文件是 `SKILL.md` 的展开版：每一条规则，依据是什么，边界在哪，以及哪些地方**没有**依据——只是本技能的判断。

## 一、为什么中文需要一套自己的受控语言

ASD-STE100 治的是英语的两类病：**一个词多个意思**，**一句话多种结构**。它的 53 条规则和 900 词受控词表都是围绕这两件事长出来的。

中文不这么坏，也不这么好在同样的地方。汉语是**意合**语言：分句之间靠语义和语序连接，逻辑关系可以完全不写出来（"下雨，不去"——因果？条件？顺序？都对）。英语是**形合**语言：`because` / `if` / `unless` 必须出现，不出现就是语法错误。所以英语的歧义主要发生在**已经写出来的连接词怎么解析**上，中文的歧义主要发生在**没写出来的部分**。

再加上一条英语里几乎不存在的机制：**零指代**。英语的限定动词必须带主语（除祈使句），所以"谁做的"在句法上是被强制的。汉语允许主语以零形式出现，而且允许多个分句共享一个从未出现的主语。这在日常对话里毫无问题，在"照着做"的文本里是事故：汉语允许说"已完成，请查收"，而这句话在句法上完全合法、在语义上完全无法执行。

所以本技能的三层不是 STE 规则的翻译，而是按中文的歧义机制重排的：

| 层 | 治的病 | 有没有权威依据 |
|---|---|---|
| 第一层 指代与逻辑 | 零指代、意合 | 语言事实，无需依据 |
| 第二层 词义锁定 | 无形式标记导致的近义词、数量词、范围词漂移 | 一半有（《立法技术规范（试行）（一）》），一半是本技能词表 |
| 第三层 情态保护 | 改写时把不确定写成了确定 | 逻辑约束，无需依据 |

## 二、第二层的官方依据：《立法技术规范（试行）（一）》

全国人大常委会法制工作委员会 2009 年印发，2011 年修正。它是给立法起草人用的，不是给普通人用的，但它治的问题和公文、制度、合同里的问题完全一样：**中文缺少形式标记，所以必须人为约定每个词只承担一种功能**。这正是受控语言的做法：STE 用 900 词表做这件事，中文用一份不足三十条的用词规范做这件事。

下面五条被本技能直接引用（条文表述为原文摘录）：

### 第 13 条「和，以及，或者」

> "和"连接的并列句子成分，其前后成分无主次之分，互换位置后在语法意义上不会发生意思变化……
> "以及"连接的并列句子成分，其前后成分有主次之分，前者为主，后者为次，前后位置不宜互换。
> "或者"表示一种选择关系，一般只指其所连接的成分中的某一部分。

落到受控中文：**「和」是并列，「以及」是主次，「或者」是选择**。三者不可互换。日常写作里最危险的是「和/或」——它把"两者都要"和"任选其一"压进同一个符号，读者只能猜。

### 第 14 条「应当，必须」

> "应当"与"必须"的含义没有实质区别。法律在表述义务性规范时，一般用"应当"，不用"必须"。

落到受控中文：**同一份文件里只留一个**。制度类默认「应当」。混用不会让读者理解错，但会让读者怀疑两者有区别，于是开始找区别——这就是无谓的阅读成本。

### 第 15 条「不得，禁止」

> "不得"、"禁止"都用于禁止性规范的情形。"不得"一般用于有主语或者有明确的被规范对象的句子中，"禁止"一般用于无主语的祈使句中。
> 不再使用"不准"、"不应"、"不能"、"严禁"等与"不得"和"禁止"相近的词语。

落到受控中文：**有主语用「不得」，无主语祈使用「禁止」，其余近义词一律不用**。这条是本技能里最"硬"的一条，因为它同时给了分工和黑名单。

### 第 24 条「以上，以下，以内，不满，超过」

> 规范年龄、期限、尺度、重量等数量关系，涉及以上、以下、以内、不满、超过的规定时，"以上、以下、以内"均含本数，"不满、超过"均不含本数。

落到受控中文：**「3 天以上」含第 3 天，「不满 3 天」不含第 3 天**。怕读者算错，就写成 `≥ 3` / `< 3`，或者加一句「（含）」「（不含）」。这是全篇最有纠纷代价的一条：期限、罚款、试用期、退款窗口都栽在这里。

### 第 25 条「日，工作日」

> "日"和"工作日"在法律时限中的区别是："日"包含节假日，"工作日"不包含节假日。

落到受控中文：**同一份文件里不许混用**，并且必须写出起算点（「自收到通知之日起」「自次日起」）。"3 日内"和"3 个工作日内"在春节前相差七天。

### 引用边界（必须说清楚）

这几条规范**管的是立法文本**。把它们用在公司通知、需求文档、外包合同上，是**类比适用**，不是法定要求。它的价值在于：它是中文世界唯一一份公开的、把"每个词只承担一种功能"写成条文的文件。本技能引用它，是因为它给出的约定是合理且可核对的，不是因为它有强制力。

## 三、标点的依据与自我限制

标点依据 GB/T 15834—2011《标点符号用法》。本技能只用到两件事：

- 中文文本用全角标点（，。：；？！「」（）），半角标点留给代码、英文串和数字。
- 顿号（、）用于并列词语，逗号（，）用于分句。

**一处需要说明的自我限制**：GB/T 15834 允许分号用于"复句内部并列关系分句之间的停顿"。所以本技能限制分号**不是因为它错**，而是因为在指令性文本里，分号几乎总是"把两个动作焊进一句"的信号。这是可读性判断，不是合规判断——不要把它说成"国标不允许分号"。

## 四、第三层：情态是内容，空词不是

这是本技能唯一一条不来自语言学、而来自改写纪律的规则，也是改写最容易翻车的地方。

**情态词**（可能、也许、大概、估计、大概率、或许、不排除、我判断）承载的是作者对命题的置信度。置信度是内容：把"可能已失败"改成"失败"，句子的真假值变了。所以情态词**永不删、永不升级**，哪怕句子因此超过字数上限。**字数上限与情态冲突时，情态赢。**

**空词**（尽快、及时、适当、必要时、原则上、酌情、相关部门）不是置信度，是**语义空缺**。它们看起来像限定，实际上什么都没限定：读者无法据此判断是否照做、何时照做、谁来做。这类词必须换成数字、条件或主体。

两者的区别可以这样测：**把词删掉，句子的真假会不会变？**

- "请求**可能**已失败" → 删掉"可能"，句子变成了一个更强的断言，真假变了。**是情态，保留。**
- "请**尽快**提交" → 删掉"尽快"，句子仍然成立，只是少了一个没有内容的催促。**是空词，必须填。**

第三条约束：**填不出来的空词，不许编。** 原文没给数字，改写者就没有权限发明一个数字。"尽快"不能变成"24 小时内"，只能变成 `【待定：提交截止时间】`，并在输出末尾用「未定」行写明缺什么、该谁补。改写的产出不只是一段更清楚的话，还是一份**待办清单**——这是受控中文和润色的分界线。

## 五、第一层：指代与逻辑的展开

### 主语落地

汉语的零指代在三种句式里最危险：

1. **状态句**：「已完成」「待确认」「未通过」——省略的是施事。
2. **被动句**：「文件被删除了」——省略的是施事，而且"被"字句在汉语里天然带不幸色彩，读者的注意力会被引到情绪上而不是责任上。
3. **责任句**：「由相关部门负责」——省略的是"哪个部门""负责什么""交付什么""什么时候"。

第三种是本技能加的一条：**责任句四件套——谁 + 做什么 + 交付什么 + 什么时候**。中文公文里最费时间的返工，就是从"相关部门配合"里倒推这四件。

### 逻辑显性

汉语把条件、因果、例外都可以省掉。省掉之后仍然合法，但读者必须自己选一种解释。改写时把逻辑关系写出来，用最少的连接词：

- 条件 → 如果 … 就 …／当 … 时／除非 … 否则 …
- 因果 → 因为 … 所以 …（可以只留"因为"或只留"所以"）
- 例外 → 除 … 外
- 让步 → 即使 … 也 …

判断标准：**读者读完这一句，会不会需要回头再读一遍来确定逻辑关系？** 会，就是没写清。

### 句长

- 指令句 ≤ 25 字，说明句 ≤ 40 字，按汉字计（标点不计，连续的英文/数字串按 1 个字计）。
- 为什么中文的上限比英文高：一个汉字的信息密度约等于 1.5–2 个英文词，STE 的 20 词上限换算成中文约 12–15 字，这个数字对中文太紧，会逼人删信息。25/40 是经验值，不是国标。

## 六、自定词表的边界

第二层里标「词表」的部分（行话、套话、空词、虚动词、同义组）是本技能自己定的，**不是标准**。三点说明：

1. **它是意见，只是可核对的意见。** 「赋能」「抓手」「闭环」不指任何具体动作，这是可论证的；但"哪些词算行话"的边界是划出来的，不是发现的。词表在 `lexicon.md`，团队可以改，但只应有一份。
2. **它不追新。** 行话每年换一批，词表会过期，`scripts/zh-lint.py` 的 `BUZZWORD` 需要跟着更新。宁可漏，不要误伤——一个把正常用词打成行话的 linter，会让人关掉它。
3. **同义组只收真正可互换的词。** 「错误 / 故障 / 失败」是三个不同概念，不收；「删除 / 移除 / 清除」在大多数产品语境里指同一件事，收。

## 七、和 ASD-STE100 的对应关系

| STE 规则 | 受控中文的对应 | 说明 |
|---|---|---|
| 一词一义（900 词表） | 第二层 近义词锁定 + 一词一义 | STE 靠版权词表，中文靠官方规范 + 项目词表，所以这里**可以**核对，不需要降级成"方向" |
| 主动语态 | 「被」字句无施事（建议类） | 汉语的被动不带形态标记，所以只兜"被 + 动词 + 句末"这个子集 |
| 不省略成分 | 第一层 主语落地 | 这是中文版里权重最高的一条，英文里权重最低 |
| 一句一指令 | 第一层 一句一动作 | 一致 |
| 句长 20/25 词 | 25/40 字 | 按汉字密度重算 |
| 不用分号 | 不用分号串动作 | STE 全面禁用，中文只禁"焊动作"的用法 |
| 名词簇 ≤ 3 词 | 「的」链 ≤ 2 层 | 英语名词前置堆叠，汉语用「的」链前置，机制不同但效果一样 |
| 简单时态 | 不适用 | 汉语没有时态，只有体标记（了 / 着 / 过），不构成歧义源 |
| 保留情态 | 第三层 情态保护 | 一致，且优先级最高 |
| — | 第一层 逻辑显性 | **STE 没有对应项**：英语不写连接词是语法错误，不需要这条规则 |
| — | 第二层 义务 / 并列 / 范围 / 时限锁定 | **STE 没有对应项**：英语没有「应当/必须」的官方分层，也没有「以上含本数」的国标惯例 |

最后两行是本技能存在的理由。一份把 STE 规则逐条翻译过来的中文技能，会在这两行上留空——而这两行恰好是中文工作文本出事最多的地方。

## 九、这份技能不做的事

- 不提供项目级术语表的自动维护。跨文档的"一词一义"需要人维护一份术语表，本技能只在单篇内检查。
- 不判断改写是否保住了原意。linter 零违规只说明配置的规则没找到问题。
- 不给法律意见。合同和条款改完必须法务过一遍。
