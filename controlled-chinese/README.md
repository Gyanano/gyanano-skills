# 受控中文 · Controlled Chinese

一个 agent skill：把**要被照着执行、而读者问不到作者**的中文，改写成只有一种读法的中文。

读者是谁：跨部门同事、外包、供应商、三个月后的自己、以及正在执行你 prompt 的 AI。他们的共同点不是"看不懂"，而是**读完之后不确定该做什么，而且没法回头问一句**。

## 为什么不是 STE 的中文版

ASD-STE100 治英语的两类病：一个词多个意思、一句话多种结构。把它的 53 条规则逐条翻译成中文，会漏掉中文真正出事的地方：

| 中文的歧义源 | 长什么样 | 英语为什么没这条 |
|---|---|---|
| **零指代** | 「已完成，请查收。」谁做的？谁收？ | 英语几乎不允许省略主语 |
| **意合** | 「文件没备份会丢。」条件？警告？陈述？ | 英语必须写 if / because / unless |
| **空词** | 尽快、适当、必要时、原则上、相关部门 | 英语的 hedge 是 may / might（信心），中文的空词是**没想清楚** |
| **数量与范围** | 「3 日以上」含不含第 3 天、算不算节假日 | 英语没有「以上含本数」的国标惯例 |

最后一行不是文风问题，是纠纷来源。而它在中国**有官方的答案**：《立法技术规范（试行）（一）》第 24 条——「以上、以下、以内」均含本数，「不满、超过」均不含本数；第 25 条——「日」含节假日，「工作日」不含；第 13、14、15 条分别规定了「和 / 以及 / 或者」的主次、「应当 / 必须」的统一、「不得 / 禁止」的分工。

这份规范是给立法者写的，但它是中文世界唯一一份公开的、把"每个词只承担一种功能"写成条文的文件。受控中文直接引用它。

**这是本技能和"STE 中译版"最实质的差别**：英文受控词表有版权、不能复制，所以 STE 技能只能把词汇规则降级成"方向"；中文这一层是公开的、官方的、可引用的，所以它可以被**核对**。

## 它做什么

1. **选档。** 执行档（制度、SOP、通知、条款、工单、报错、工具描述、agent 指令）三层规则全执行；阅读档（README、复盘、公众号）第一层和第三层全执行，第二层里只有"有纠纷代价"的那几条仍强制。
2. **通读一遍**，先弄清它改完之后还必须说什么。
3. **逐句标出违规**：无主句、逗号链、空时间/空条件/空数量/空主体、虚动词、行话、套话、双重否定、义务词轮换、范围词未标含不含本数、时限单位混用、超长句、「的」链、列表项没说完。
4. **改写，但不许补事实。** 原文没给数字，「尽快」就不能变成「24 小时内」——只能变成 `【待定：…】`，并在正文后加一行「未定」，写明缺什么、该谁补。
5. **默认只输出改写后的正文**，不加开场白、不加档位说明、不数违规条数。另有两行允许的附加：「未定：」和「保留原样：」。
6. 要看理由（「给我看 diff」「违反了哪些规则」），输出「违反的规则 / 原文 / 改写后」三列表格。

## 「情态是内容，空词不是」

这是整份技能的核心判断，也是最容易改坏的地方。判别口径：**把词删掉，句子的真假会不会变？**

- **会变 → 情态，保留。** 「请求**可能**已失败」删掉「可能」就成了另一个断言。哪怕因此超过字数上限，也保留。
- **不会变 → 空词，处理掉。** 「请**尽快**提交」删掉「尽快」句子仍然成立，只是少了一个没有内容的催促。必须换成时间、条件或数字。

英文的 hedge（may / might）和中文的空词（尽快 / 适当 / 必要时）在语言学的同一栏里，但在受控写作里必须**反向处理**：一个要留，一个要消灭。分界线就是这句话的真假变不变。

## linter

`scripts/zh-lint.py`，仅用标准库，确定性，带 `--selftest`。

```bash
python3 scripts/zh-lint.py --selftest                 # 30 多条断言，含情态必须干净
python3 scripts/zh-lint.py 通知.md                    # 人读输出
cat 通知.md | python3 scripts/zh-lint.py --json       # 结构化
python3 scripts/zh-lint.py --baseline 5 存量制度.md    # 存量文档接入
python3 scripts/zh-lint.py --disable buzzword 稿件.md  # 关掉某条
```

退出码：`0` 通过，`1` 硬违规超过 baseline，`2` 用法错误。建议类发现（「被」字句无施事、无主状态句、「的」链、逗号链、半角括号、禁止词）永不导致失败。

**它查什么**：分号串联、半角标点、空时间/空条件/空数量/空主体、虚动词、行话、套话、双重否定、义务词轮换、范围词未标含不含本数、时限单位混用、超长句（指令 25 字 / 说明 40 字，按汉字计）、无主状态句、「被」字句、「的」链、同义轮换、列表项以「、/和/或/以及」结尾、三个以上逗号分句又没有任何逻辑词。

**它不查什么**（这三条比"查什么"更重要）：

- **零指代**。除「已 / 待 / 未」开头的高频子集，判断一个句子有没有主语需要句法分析，正则做不到。
- **意合**。除"三个以上逗号且没有逻辑词"这个粗筛，判断两个分句是因果还是并列要读懂。
- **改写有没有改掉原意**。linter 不比对原文和改写。零违规只说明配置的规则没找到问题。

所以正确用法是：**先跑 linter 拿到机械部分，再逐句读剩下三类。** 反过来不行——只跑 linter 的改写会让文本看起来干净，而空位还在。

`examples/before-after.md` 里八段改写文本，各自单独跑一遍 linter 都是零违规（写这份文档时逐段验的）。整份 `before-after.md` 不会 lint 干净，也不是缺陷：规则表引用的正是它禁止的那些词。

## 安装

把整个目录放进你的 agent 读取 skill 的位置。Claude Code：

```bash
cp -r skills/controlled-chinese ~/.claude/skills/controlled-chinese
```

也可以只把 `SKILL.md` 当一份写作规范读——它自己就够用，`references/` 和 `scripts/` 是展开和工具。

## 用法

直接说要干什么：

```
把这条通知写成没人会误解的样子
这段需求读起来太绕，帮我改清楚
这条制度里"3 天以上"到底含不含第 3 天？
让 agent 读不错：把这段 prompt 收紧
disambiguate this Chinese spec
```

想要理由，加一句「给我看 diff」或「违反了哪些规则」，会得到三列表格。

## 范围

**给谁用**：制度、SOP、通知、工单、报错、工具描述、agent 指令、system prompt、需求文档、合同与规则条款——任何"读完要照着做"的中文。

**不给谁用**：创意文案、营销稿、文学、需要语气和留白的地方。受控中文是故意平淡、字面化的。

**一条必须说在前面的限制**：它修的是**形式**，不是**内容**。一段空话改完，会变成一段干净、简短、标点正确的空话。文本本身没东西可说，就直说，别粉饰。

**另一条**：`references/lexicon.md` 里标「词表」的部分是本技能自己定的，不是国标，可以改——但一个团队只该有一份。标「国标」的部分引用《立法技术规范（试行）（一）》，可以核对，但它管的是立法文本，用在公司制度上是**类比适用**，不是法定义务。合同和条款改完仍然要法务过一遍。

## 文件

```
controlled-chinese/
├── SKILL.md                      # 技能本体：三层规则、扫描清单、流程、输出格式、边界
├── references/
│   ├── rules.md                  # 规则全集与依据（含《立法技术规范》原文摘录）
│   └── lexicon.md                # 词表：锁定类 / 填空类 / 删除类 / 不许动
├── examples/
│   ├── before-after.md           # 八段改写 + 一个"不要改"的例子
│   └── linter-edge-cases.md      # 有意写坏的测试夹具
└── scripts/
    └── zh-lint.py                # 确定性 linter，stdlib only，带 selftest
```
